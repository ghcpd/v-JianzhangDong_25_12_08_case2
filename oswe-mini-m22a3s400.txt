Vulnerabilities discovered (file: inputs.py — lines refer to original file)
1) Hardcoded secrets (inputs.py lines 11–13)
   - PAYMENT_TOKEN, MAIL_SERVER_KEY, INTERNAL_AUTH stored in source.
   - Severity: High

2) Weak hashing & predictable token generation (inputs.py lines 18–21)
   - MD5 over username+secret used for tokens.
   - Severity: High

3) SQL Injection (inputs.py lines 24–31)
   - Query built via string interpolation (q = "... '%s'" % uid)
   - Severity: Critical

4) Insecure server-side requests (SSRF/unrestricted outbound calls) and no timeouts (inputs.py lines 34–41)
   - notify_url accepted without validation; requests.post used without timeout
   - Severity: High

5) Arbitrary file read / path traversal (inputs.py lines 44–47)
   - update_records opens arbitrary file path from client
   - Severity: Critical

6) Command Injection via subprocess shell=True (inputs.py lines 50–53)
   - export_data builds a shell string and calls subprocess.Popen(shell=True)
   - Severity: Critical

7) Missing authentication on critical endpoints (inputs.py lines 56–85)
   - profile, transfer, config, export endpoints lacked auth
   - Severity: High

8) Debug mode enabled (inputs.py line 88)
   - app.run(debug=True) — Werkzeug debugger risk
   - Severity: Critical

9) Sensitive logging of user input (inputs.py lines 37–38)
   - Printing transfer line with payload may leak info
   - Severity: Low

10) No TLS verification / no timeouts on outgoing requests (inputs.py line 40)
    - Could lead to blocking/DoS and exposures
    - Severity: Medium
