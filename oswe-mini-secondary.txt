## 🔧 Security fixes applied (in inputs.py)
I implemented the following secure changes (high-level):

- Secrets: Moved to environment variables `PAYMENT_TOKEN`, `MAIL_SERVER_KEY`, `INTERNAL_AUTH`.
- Authentication: Added `_require_token()` and enforced token header checks for sensitive endpoints.
- Token generation: Used HMAC-SHA256 (server-side key) instead of MD5.
- SQL: Changed to parameterized queries and validated `uid` (only numeric IDs accepted).
- SSRF: `notify_url` validated to accept HTTPS & optional allowlist (via `NOTIFY_WHITELIST` env var).
- File reads: Only allow config file names from a fixed `CONFIG_DIR`, validate filenames, prevent traversal.
- Shell usage: Replaced shell-based zipping with `zipfile` module — no shell=True.
- Logging: Replaced `print` with logging and redacted sensitive data.
- Debug mode: Disabled debug mode in the in-script run path.

Each change includes a description, severity, and secure snippet in report.json.
